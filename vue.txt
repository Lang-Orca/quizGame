## 1. L'Algorithme de Répartition et de Bonus (Algorithme du Maître)
Lorsque le maître clique sur "Boucler le salon", l'application exécute cette logique mathématique précise :

   1. Déterminer le nombre d'équipes $N$ : Pour $X$ participants, l'application choisit la puissance de 2 immédiatement inférieure ou égale (dans votre cas, vous ciblez 4 équipes).
   2. Distribution équitable : L'algorithme distribue les joueurs un par un dans les équipes pour maximiser l'équilibre.
   * Exemple avec 10 joueurs : Équipe 1 (3 joueurs), Équipe 2 (3 joueurs), Équipe 3 (2 joueurs), Équipe 4 (2 joueurs). [1] 
   3. Calcul du Bonus : L'application repère la taille maximale d'une équipe (ici 3 joueurs).
   * L'Équipe 1 et 2 ont 3 joueurs $\rightarrow$ 0 point de bonus.
      * L'Équipe 3 et 4 ont 2 joueurs (il manque 1 membre) $\rightarrow$ +10 points de bonus (par exemple) appliqués d'office au score global de l'équipe ou à leur champion lors du duel.
   
## 2. Le Système de Sécurité anti-triche (Verrouillage du Questionnaire)
Pour garantir qu'aucun joueur (ni même le maître) ne puisse lire les réponses à l'avance, la base de données sqflite appliquera un statut strict :

* Structure de la table Questionnaires : Elle contient un champ statut (valeurs : 'verrouille', 'deverrouille').
* Pendant la génération (Online) : Le document est traité, l'IA renvoie les questions. Elles sont immédiatement insérées dans sqflite avec le statut 'verrouille'.
* Côté Code (Sécurité) : Les écrans de consultation des questionnaires filtrent strictement les données. Si un questionnaire a le statut 'verrouille', l'application refuse d'afficher son contenu à l'écran, affichant simplement un cadenas 🔒.
* Fin de partie : Dès que le tournoi affiche son écran de fin, le statut passe à 'deverrouille'. Le questionnaire devient accessible dans l'historique pour révision.

-- Table des questionnaires (Générés par l'IA ou publics téléchargés)CREATE TABLE questionnaires (
    id TEXT PRIMARY KEY, -- UUID

## 🧮 Algorithme de Répartition et Calcul des Bonus
Voici la logique JavaScript/TypeScript à exécuter côté Maître de salon lorsque la session est bouclée. Cet algorithme calcule le nombre optimal d'équipes (puissance de 2) et attribue le bonus de compensation.

interface Joueur {
  id: string;
  pseudo: string;
}
interface Equipe {
  id: string;
  nom: string;
  membres: Joueur[];
  bonusPoints: number;
}
function genererTournoi(listeJoueurs: Joueur[]): Equipe[] {
  const X = listeJoueurs.length;
  if (X < 2) throw new Error("Il faut au moins 2 joueurs pour démarrer.");

  // 1. Déterminer le nombre d'équipes N (Puissance de 2 immédiatement inférieure ou égale)
  // Si 10 joueurs -> Math.floor(log2(10)) = 3 -> 2^3 = 8 équipes de base
  // Mais selon vos préférences de flux, on peut forcer un plancher minimal (ex: 2 ou 4 équipes min si possible)
  let N = Math.pow(2, Math.floor(Math.log2(X)));
  if (N > 16) N = 16; // Limite optionnelle pour ne pas disperser les joueurs

  // Initialisation des équipes
  const equipes: Equipe[] = Array.from({ length: N }, (_, i) => ({
    id: `equipe_${i + 1}`,
    nom: `Équipe ${i + 1}`,
    membres: [],
    bonusPoints: 0,
  }));

  // 2. Distribution équitable des joueurs (Round-Robin)
  // On mélange les joueurs aléatoirement avant la distribution
  const joueurs Melanges = [...listeJoueurs].sort(() => Math.random() - 0.5);
  joueursMelanges.forEach((joueur, index) => {
    const cibleEquipe = index % N;
    equipes[cibleEquipe].membres.push(joueur);
  });

  // 3. Calcul du Bonus de Consolation pour les équipes en sous-nombre
  // On trouve la taille de la plus grande équipe formée
  const tailleMax = Math.max(...equipes.map(e => e.membres.length));
  const VALEUR_BONUS_PAR_MEMBRE_MANQUANT = 10; // À ajuster selon votre équilibrage

  equipes.forEach(equipe => {
    const membresManquants = tailleMax - equipe.membres.length;
    if (membresManquants > 0) {
      equipe.bonusPoints = membresManquants * VALEUR_BONUS_PAR_MEMBRE_MANQUANT;
    }
  });

  return equipes;
}

## 🌐 Flux de Synchronisation (Firebase vs LAN)
Pour l'implémentation de la connectivité dans votre application React Native CLI :

* En Ligne (Firebase Realtime Database) :
Le Maître crée un nœud /sessions/CODE6D. Les participants écoutent ce nœud via .on('value', ...). Lorsque le Maître clique sur verrouiller, il calcule les équipes localement avec l'algorithme ci-dessus et pousse la structure de l'arbre du tournoi sur Firebase pour que tous les téléphones mettent à jour leur affichage instantanément.
* Hors Ligne (LAN local) :
Vous utiliserez des librairies de socket (comme react-native-tcp-socket ou des serveurs HTTP légers en natif) couplées à un protocole ZeroConf/NSD (comme react-native-zeroconf). Le Maître diffuse sa présence sur le réseau local. Les téléphones clients scannent, découvrent l'adresse IP du Maître et s'y connectent en un clic via une connexion WebSocket locale.

Pour passer à l'écriture des modules, préférez-vous que l'on mette en place le prompt IA structuré pour générer les questions au format JSON compatible avec votre table SQLite, ou l'implémentation de la découverte réseau locale (ZeroConf/NSD) en React Native ?
